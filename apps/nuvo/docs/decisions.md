# nuvo 결정 기록

프로젝트의 **왜**를 남기는 문서입니다. 무엇을 정했는지뿐 아니라 **어떤 선택지를 봤고, 무엇을 버렸고, 어떤 자료를 근거로 했는지**를 적습니다. 나중에 "그때 왜 이렇게 했지"를 코드나 채팅 기록을 뒤지지 않고 여기서 찾습니다.

**규칙**
- 결정·잠정·제안이 생기거나 바뀔 때마다 아래에 **덧붙입니다**(위에 새 항목). 지우지 않고, 뒤집히면 새 항목에서 "D-00N을 뒤집음"이라고 씁니다
- 한 항목 = 날짜 · 상태(확정/잠정/제안) · 결정 · 본 선택지 · 이유 · 자료(출처·조사·계산) · 관련 문서
- 세부 수치·표는 해당 설계 문서에 두고 여기서는 링크합니다. 이 문서는 요약과 이유입니다
- 사소한 구현 선택은 코드 주석·커밋 메시지로 충분합니다. 여기 적는 건 **제품·정책·구조·돈**에 관한 것

상태 표시: **확정** = 그대로 진행 / **잠정** = 이 기준으로 진행하되 바뀔 수 있음 / **제안** = 기본값일 뿐 아직 결정 아님

### D-018 · 확정 · 신고·차단·지원 연락처 구현 방식 (work-plan ⑤)
- **신고**: 멤버(viewer+) 누구나 Space 안 사진·멤버를 신고. 사유 5가지(부적절·개인정보·괴롭힘·아동 안전·기타) + 메모. Space 관리자(admin+)만 목록을 보고 "처리함 / 문제 없음"으로 닫음. 운영자에게는 `SUPPORT_EMAIL`로 메일, 아동 안전은 제목에 [긴급]
  - 본 것: 익명 신고 / 피드에 신고 표시 / 운영자만 처리. 버린 이유: 가족 공간이라 익명은 오히려 불신을 키우고(신고자 이름은 관리자에게 보임), 피드는 멤버 모두가 봄, 운영자만 처리하면 1인 운영에 부담이 몰림
  - 사진이 지워져도 신고 기록과 당시 해시는 남김(운영자가 같은 원본을 찾을 수 있게). 지운 사진의 썸네일은 다시 서명하지 않음
  - 남용 방지: 한 사람 하루 20건
- **차단**: 별도 기능이 아니라 **"내보내고 차단"**(`?block=1`) — `space_blocks` 표. 차단된 사람은 유효한 초대 링크로도 403. 관리자가 풀 수 있음
  - 본 것: `space_members`에 blocked 상태 / 사용자 간 전체 차단. 버린 이유: 멤버 행을 남기면 권한 검사 곳곳을 바꿔야 함, 사용자 간 차단은 가족 Space에 과함
- **지원 연락처**: `SUPPORT_EMAIL` 설정 하나 → `GET /api/config`로 랜딩·설정·신고 창에 표시. 도메인이 정해질 때까지 비워 둠(비면 숨김)
- 근거: Apple 1.2(필터·신고·차단·공개 연락처), Google UGC(사용자 일부에게라도 보이면 대상, 신고·차단) — [media-security.md](media-security.md) 3.3·4.4
- 남은 것: 약관 동의(④), 운영자 처리 화면(1차는 DB 직접)

### D-017 · 확정 · 용량·구독 구현 방식 (work-plan ②·③)
- 소유자 용량은 **라이브러리별 `used_bytes`를 그대로 두고 검사만 합계로**: 개인 라이브러리 + 소유한 Space 라이브러리의 합 vs 개인 `quota_bytes`. Space 행의 `quota_bytes`는 0
  - 본 것: 라이브러리마다 용량을 두고 소유자가 나눠 주기 / Space 업로드를 소유자 라이브러리에 직접 적립. 버린 이유: 전자는 사용자가 배분해야 하고, 후자는 삭제·참조 계산(`removeAssets`)을 다 바꿔야 함
  - 대가: 동시 업로드 때 합계 검사에 틈이 있음(완료 단계에서 재검사해 되돌림). mvp.md "알려진 한계"에 적음
- 구독 판단은 `subscriptions` 표 + `subscriptionOf` 함수 하나. 1차는 `manual`만. 응답 코드 **402**
- Space 소유자의 구독이 끝나면 **보기 유지, 올리기만 막음**(D-011 후속 제안을 그대로 채택)
- 로컬 테스트용 `POST /api/dev/subscribe`(운영 404). 운영 수동 구독은 SQL
- 문서: [work-plan.md](work-plan.md), [mvp.md](mvp.md) "용량·구독", [developer-guide.md](developer-guide.md) "수동 구독"

### D-016 · 확정 · 가족 올리기·Space 용량·위치 공유
- ① **구독 없는 가족도 소속된 Space에는 올릴 수 있다.** 자기 개인 사진함(백업)은 구독자만. "가족"은 초대받아 Space 멤버가 된 사람(그룹 소속)으로 한정
- ② **Space 용량은 소유자의 10GB에서 차감.** 가족이 올린 사진도 소유자 몫. 차면 Space 전체 업로드가 멈추고 소유자에게 알림
- ③ **Space로 보낼 때 위치(lat/lng)는 기본 복사 안 함, 보낼 때 "위치도 공유" 선택 옵션.** 원본 파일 EXIF 처리(안내만 / 제거본 / 다운로드 시 제거)는 별도 미결(media-security 2.1)
- 본 것: ① 올리기도 구독자만 → 가족 공유가 반쪽이 됨 / ② 올린 사람 각자 차감 → 구독 없는 가족이 올릴 수 없게 됨, Space 별도 용량 → 상품이 둘이 됨 / ③ 항상 복사 → 집 위치 노출, 항상 제거 → 여행 사진 지도가 안 됨
- 이유: 결제자 한 명이 가족을 데려오는 구조(D-011)와 일관됨. 위치는 기본 보호, 원할 때만 공개
- 영향: work-plan ②·③ 코드 시작 가능. `SPACE_QUOTA_GB` 제거, 업로드 허용 조건 = (구독자 and 자기 사진함) or (Space 멤버 and 소유자 한도 남음)
- 문서: [service-plan.md](service-plan.md), [work-plan.md](work-plan.md), [media-security.md](media-security.md) 2.1

- 버린 이유: multipart는 R2의 sha256 검증을 못 쓰고, 그 검증 위에 업로드 영수증(HMAC)과 내용 주소 저장이 서 있음. 720p·2Mbps 3분이 약 45MB라 지금의 100MB 단일 업로드로 충분
- 핵심 설계: 압축 사본은 원본과 해시가 달라 타임라인 합치기·중복·연결이 깨짐 → `assets.source_sha256`으로 원본 해시 연결
- 상태: 세부 V1~V11이 제안. 3차 단계에서 확정
- 문서: [roadmap-video-classification.md](roadmap-video-classification.md) "동영상 세부 결정"
