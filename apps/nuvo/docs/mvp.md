# nuvo MVP

흩어진 사진을 한곳에 모아 보고, 가족·친구와 함께 쌓아가는 프라이빗 사진 서비스.

- 배포 전에 사람이 해야 할 일: [developer-guide.md](developer-guide.md)
- 색과 테마: [design-system.md](design-system.md)

## 범위

| MVP (구현 완료) | 이후 단계 |
|---|---|
| 이 PC 폴더 참조 (업로드 없이 보기, 로그인 없이도 사용 가능) | 외부 클라우드 연동 (Google Photos/Drive, OneDrive, Dropbox, MYBOX) |
| nuvo 저장소 업로드 (드래그·선택, 중복 업로드 건너뜀) | 모바일 백업 앱 (Expo), 데스크톱 앱 (Tauri) |
| 통합 타임라인 (이 PC + nuvo, 같은 사진은 한 칸) | **동영상** (서버 변환 필요) |
| PC 사진 골라서 nuvo에 백업 | 결제·유료 플랜 (지금은 용량 제한만) |
| Space: 생성, 초대 링크, 함께 업로드, 역할, 내보내기·나가기, 소유권 이전 | 앨범, 휴지통(30일 보관), 게스트 링크 |
| Space 피드와 실시간 알림 (WebSocket) | AI 검색, 얼굴 인식, 지도 보기 |
| 유사 중복 정리 (리사이즈·재압축본 탐지) | 큰 파일 직접 업로드 (presigned multipart) |
| 다크·라이트 테마, 강조색 3종, 랜딩 셰이더, 3D 시간 터널 | |
| 이메일 가입(인증 메일 필수)·비밀번호 재설정, Google 로그인 (카카오는 키만 넣으면 됨) | |
| 계정 삭제 | |

## 무료 운영 한도 (2026-11-04 결정)

MVP는 클라우드 무료 사용량 안에서 운영합니다. 유료 플랜은 다음 단계입니다.

| 항목 | 값 | 근거 |
|---|---|---|
| 개인 사진함 | 2GB (약 600장) | `PERSONAL_QUOTA_GB` |
| Space | 5GB (약 1,500장) | `SPACE_QUOTA_GB` |
| **서비스 전체** | **8GB** | `STORAGE_CAP_GB`. R2 무료 10GB는 계정 공용 (아래 "계정 공용 한도") |

- 전체 저장량(등록된 원본 + 완료 전·삭제 대기 업로드, 썸네일 몫 12% 포함)이 상한을 넘는 업로드는 507로 거부하고, 화면은 남은 업로드를 모두 멈춥니다. 이미 있는 사진에 연결(link)하는 것은 저장량이 늘지 않아서 막지 않습니다.
- 동시에 올리면 상한을 조금 넘을 수 있어서, 계정 배분(nuvo 8 + portfolio-web 1)에서 1GB를 여유로 남겼습니다.
- "이 PC 폴더" 사진은 서버에 올라가지 않아서 한도와 상관없습니다.
- 유료 플랜 후보: Space 단위 100GB, 월 3,900원 (꽉 채워도 R2 원가보다 수입이 큼). 한 사람당이 아니라 Space당 용량으로 묶습니다.

### 계정 공용 한도 (2026-11-04)

Cloudflare 무료 한도는 Worker마다가 아니라 **계정 전체**에 걸립니다. 같은 계정의 portfolio-web(yhy-site)과 나눠 씁니다. 같은 표가 `apps/site/docs/guides/cost-guard.md` "계정 공용 한도"에 있으니, 바꿀 때는 두 곳을 같이 고칩니다. **임시 배분**입니다: nuvo를 새 Cloudflare 계정으로 옮기면(루트 `docs/monorepo.md`) 이 표를 지우고 `STORAGE_CAP_GB`를 9로 되돌립니다.

**Resend**도 지금은 portfolio-web과 같은 계정입니다. 두 앱 상한(각 하루 80통)을 합치면 무료 100통을 넘으므로, **Resend 계정을 나누기 전에는 운영에 `RESEND_API_KEY`를 넣지 않습니다.**

| 자원 | 계정 무료 한도 | nuvo | portfolio-web | 여유 |
|---|---|---|---|---|
| R2 저장 | 10GB | 8GB (`STORAGE_CAP_GB`, 코드로 막음) | 1GB 안 (RAG 원본·이미지, 로컬 CLI로만 올림) | 1GB |
| Workers 요청 | 하루 10만 | 상한 없음 (크론 하루 96회 포함) | 상한 없음 (IP별 순간 제한) | 둘 합이 7만을 넘으면 다시 나눔 |
| Workers AI | 하루 1만 뉴런 | 쓰지 않음 | 8,000 (`AI_DAILY_NEURON_CAP`) | 2,000 |
| D1 · KV · Vectorize | — | 쓰지 않음 (Postgres·Durable Object) | 전부 | — |

- nuvo가 Workers AI·D1·KV를 쓰기 시작하면 이 표부터 고칩니다.
- R2 사용량은 대시보드 R2 개요에서 계정 합계로 봅니다 (portfolio-web `/admin/usage`도 계정 합계).

### 메일 상한 (2026-11-04)

Resend 무료는 하루 100통·월 3,000통입니다. 서비스 전체로 **하루 80통·월 2,800통**에서 멈춥니다 (`MAIL_DAILY_CAP`·`MAIL_MONTHLY_CAP`, `wrangler.jsonc` vars).

- 공용 모듈 `@yhy/cf-kit/budget`(portfolio-web과 같은 코드)에 카운터는 Postgres `usage_counter` 표(`worker/lib/usage.ts`). upsert라 동시에 와도 정확히 셉니다
- Resend로 **실제로 보낸 메일만** 셉니다. 로컬 보관함(outbox)과 발송 실패는 세지 않습니다
- 상한에 닿으면: 이메일 가입은 미리 429 `MAIL_BUDGET`("메일 발송 한도에 닿았어요")으로 막아 인증 메일 없이 계정만 생기지 않게 합니다. 비밀번호 재설정·인증 메일 재발송은 응답을 바꾸지 않고 보내지 않습니다(응답 차이로 가입 여부를 드러내지 않게). Google·카카오 로그인은 그대로
- 80%·100%는 Workers 로그에 `[budget]`으로 남습니다 (알림 채널 없음)

## 아키텍처

```
브라우저 (Vite + React SPA)
  ├─ Web Worker 풀: SHA-256 · EXIF · 썸네일(512/2048, WebP) · dHash · blurhash · HEIC 디코딩(WASM, 필요할 때만)
  ├─ IndexedDB: 이 PC 폴더 핸들, 사진 인덱스, 썸네일 (서버로 보내지 않음)
  └─ Hono RPC 클라이언트 (API 타입 자동 공유)
        │
Cloudflare Worker 1개 (정적 SPA + API)
  ├─ /api/*    Hono · Better Auth · zod 검증
  ├─ /m/*      사진 서빙: HMAC 서명 검증(DB 조회 없음) → 엣지 캐시 → R2
  ├─ R2        o/{sha256} 원본, t/{sha256}/{512|2048} 썸네일 (내용 주소)
  ├─ Durable Object SpaceHub   Space별 WebSocket 방송 (Hibernation)
  └─ Hyperdrive → Postgres (로컬 Docker / 운영 Neon), Drizzle ORM
```

## 계획에서 바뀐 결정

| 처음 계획 | 실제 구현 | 이유 |
|---|---|---|
| presigned URL로 R2에 직접 업로드 | **Worker가 R2로 스트리밍** | 로컬에서 그대로 테스트 가능하고, R2 S3 키 발급이 필요 없음. R2가 sha256을 검증해서 키와 내용이 항상 일치. 사진은 100MB 한도 안이라 충분. 동영상 단계에서 presigned 방식 추가 |
| 서버 미디어 컨테이너 | **브라우저에서 처리** | MVP의 사진은 전부 브라우저에서 들어옴. 외부 클라우드 연동 단계에서 컨테이너 도입 |
| 앨범 테이블 | 제외 | MVP는 타임라인과 Space에 집중 |
| 휴지통 30일 | 즉시 삭제 (확인 창) | 다음 단계 |

## 데이터 모델

```
user / session / account / verification   Better Auth
blobs        물리 파일 (sha256 유일, refCount). 여러 Asset이 공유, 참조 0이면 R2에서 삭제
libraries    personal(userId) | space(spaceId), quotaBytes, usedBytes
assets       라이브러리 안 사진 1장 (blobId, uploadedBy, takenAt, gps, camera, dhash, blurhash)
spaces / space_members(owner|admin|editor|viewer) / invites(7일, 10명)
activities   Space 피드. 같은 사람이 10분 안에 연달아 올리면 한 줄로 합침
```

이 PC 사진은 서버 DB에 없습니다. 브라우저 IndexedDB에만 있고, 타임라인에서 sha256으로 nuvo 사진과 합칩니다.

**이 PC 폴더는 계정이 아니라 기기(브라우저 프로필) 단위로 공유합니다.** (2026-11-04 결정)
- 같은 PC·같은 브라우저를 쓰는 가족은 로그인한 계정과 상관없이 같은 폴더 목록과 썸네일을 봅니다. 로그아웃해도 지우지 않습니다.
- 원본을 열려면 브라우저의 폴더 접근 허락이 필요합니다.
- 다른 기기, 다른 브라우저 프로필, Space 멤버에게는 보이지 않습니다. 백업한 사진만 서버(내 개인 사진함)에 올라갑니다.
- 로그인 상태에서는 "백업됐는지" 확인하려고 해시(sha256)만 서버에 보냅니다. 서버는 저장하지 않고, 내가 접근할 수 있는 사진함 안에서만 비교합니다.

## 보안 설계 (smoke 테스트로 검증)

- **남의 사진 존재 여부를 알 수 없음.** 업로드 전 "이미 있음" 판정은 내가 접근할 수 있는 라이브러리 안에서만 합니다. 썸네일 업로드도 영수증이 없으면 사진이 있든 없든 똑같이 403입니다.
- **해시만 알아서는 남의 사진을 가져올 수 없음.** 업로드 완료 시 원본을 실제로 올렸다는 서버 영수증(HMAC)이 필요합니다.
- **해시와 내용이 다른 업로드는 거부.** R2가 sha256을 검증합니다.
- **이미지 형식만 업로드 가능.** 사진 응답에는 `CSP sandbox`와 `nosniff`를 붙여서, 같은 도메인 XSS를 막습니다. 이미 등록된 사진을 다시 올려도 처음 형식이 유지됩니다.
- **이미 등록된 사진의 썸네일은 덮어쓸 수 없음.** 썸네일은 원본을 방금 올린 사람(영수증)만 올릴 수 있습니다.
- **사진 URL은 6~12시간 뒤 만료.** 브라우저 캐시는 `private`, 엣지 캐시는 하루입니다.
- **지운 사진은 피드에서도 사라짐.** 피드 썸네일은 지금 Space에 있는 사진만 서명합니다. 마지막 사본을 지우면 R2 파일도 바로 지웁니다.
- **권한:** 참여자는 자기가 올린 사진만 삭제할 수 있습니다. 관리자 지정·관리자 역할 변경·관리자 내보내기와 소유권 이전은 소유자만 합니다. 역할 변경은 멤버 행을 잠그고 처리해서, 동시에 요청해도 소유자는 한 명입니다. 소유자는 소유권을 넘기기 전에는 나갈 수 없습니다.
- **내보내면 실시간 연결도 끊김.** 허브가 연결마다 사용자를 기억해 두었다가 내보내기·나가기·Space 삭제·탈퇴 때 끊습니다.
- **로그인:** 이메일은 인증 메일을 확인해야 로그인됩니다 (남의 이메일 선점 방지). 로그인·가입·메일 발송 횟수를 IP 기준으로 제한하고(DB 저장), 비밀번호를 재설정하면 모든 기기에서 로그아웃됩니다. 세션 쿠키 캐시는 쓰지 않아서 로그아웃·탈퇴가 즉시 반영됩니다. 재설정 요청은 가입 여부와 관계없이 같은 응답입니다.
- **DB 캐시 끔:** Hyperdrive 쿼리 캐시를 꺼서 권한 변경·삭제가 바로 반영됩니다.
- **계정 삭제:** 세션 쿠키를 지운 뒤, 한 트랜잭션에서 라이브러리를 잠그고 사진·Space·사용자를 지웁니다. 다른 멤버가 있는 Space의 소유자는 먼저 소유권을 넘겨야 합니다.
- **저장소 정합성:**
  - 완료하지 않은 업로드는 대기 용량으로 한도에 넣습니다. 2시간 뒤 cron(15분마다)이 R2에서 지웁니다 (`r2_gc` 테이블).
  - R2 파일 삭제와 Blob 등록은 같은 sha256 잠금(advisory lock)을 잡아서 엇갈리지 않습니다.
  - 삭제와 동시에 들어온 연결(link)·보내기는 Blob 행을 잠가서 확인합니다.
- **잘못된 id 형식**은 500이 아니라 404/400입니다.

## 알려진 한계

- **이 PC 폴더 참조는 Chrome/Edge 데스크톱만** 지원합니다. 다른 브라우저는 열 때마다 폴더를 다시 골라야 합니다 (1회 스캔).
- 사진만 지원하고, 파일당 100MB까지입니다.
- 3D 보기는 최근 240장만 보여줍니다.
- **썸네일은 처음 올린 사람의 브라우저가 만듭니다.** 같은 원본 파일을 가진 사람이 먼저 올리면서 엉뚱한 썸네일을 붙이면, 뒤에 같은 사진을 올린 사람도 그 썸네일을 봅니다 (원본은 항상 정확합니다). 원본을 가진 사람만 할 수 있어서 MVP에서는 받아들이고, 외부 클라우드 연동 단계에서 서버 썸네일 생성(Cloudflare Images)으로 바꿉니다.
- 중복 정리는 nuvo 사진끼리만 합니다. PC 파일은 지우지 않습니다.
- **실기기 검증이 남아 있습니다** (developer-guide 17단계): iOS Safari 업로드 메타데이터, 대용량 폴더 스캔 시간, 저사양 기기의 3D 성능.
