# 로드맵 제안: 동영상과 자동 분류

상태: **제안 (구현 전)**. 2026-11-04 작성. 정할 것은 맨 아래에 있습니다.

전제는 지금 설계와 같습니다.
- 처리는 브라우저에서 합니다 (Web Worker). 서버 변환 컨테이너는 쓰지 않습니다.
- MVP는 무료 사용량 안에서 운영합니다 (서비스 전체 8GB, [mvp.md](mvp.md) "무료 운영 한도").

## 핵심 방향: 원본은 PC에, 가족에게는 가벼운 사본을

동영상은 사진보다 훨씬 큽니다. iPhone 4K로 1분을 찍으면 약 350MB라서, 8GB 한도는 동영상 20여 개면 찹니다.

- **이 PC 동영상:** 사진처럼 올리지 않고 nuvo 뷰어에서 바로 재생합니다. 원가는 0원입니다.
- **가족과 나눌 동영상:** 브라우저가 720p로 압축한 **공유용 사본만** 올립니다. 1분에 약 15MB이고, 원본은 PC에 남깁니다.

## 1. 동영상 수집과 자체 뷰어

### 수집 (이 PC 폴더)
| 기능 | 방법 |
|---|---|
| 동영상 찾기 | 폴더 스캔 대상에 mp4, mov, m4v 등 추가 |
| 정보 읽기 | 파일 전체를 읽지 않고 앞부분만 분석해서 촬영 시각, 위치, 길이, 해상도, 코덱을 뽑음 (mp4box.js 등, Web Worker에서 실행) |
| 대표 화면 | 영상 10% 지점의 장면을 썸네일로 저장 |
| 미리보기 줄 | 장면 10개 정도를 한 장으로 이어 붙여 저장. 마우스를 올리면 장면이 넘어감 |
| 빠른 식별 | 큰 파일 전체 해시는 느림. "크기 + 앞뒤 1MB 해시"로 먼저 식별하고, 업로드할 때만 전체 sha256 계산 |
| Live Photo | iPhone의 HEIC + 짧은 MOV 쌍을 하나로 묶어 "움직이는 사진"으로 표시. 안드로이드 모션 포토(JPEG 안의 MP4)도 꺼냄 |

### 자체 뷰어
- 타임라인에서 사진과 함께 보여주고, 동영상에는 재생 아이콘과 길이를 표시합니다.
- 마우스를 올리면 미리보기가 재생되고, 클릭하면 전체 화면 플레이어가 열립니다.
- 플레이어 기능: 탐색 막대 위 장면 미리보기, 재생 속도, 한 프레임씩 넘기기, 키보드 단축키, 사진과 같은 좌우 넘김
- 재생할 수 없는 형식(MKV, AVI, 일부 HEVC)은 대표 화면과 "다른 앱으로 열기"를 보여줍니다.
  - HEVC 재생 여부는 기기와 브라우저마다 다르므로 실기기 확인이 필요합니다.

### 공유용 업로드 (Space)
| 문제 | 해법 |
|---|---|
| 용량 | 브라우저 동영상 인코더(WebCodecs)로 720p, 약 2Mbps 사본을 만들어 올림. 서버 변환 비용 없음 |
| Worker 요청 크기 100MB 제한 | Worker에서 R2 **분할 업로드(multipart)**를 직접 호출. "Worker가 R2로 전달" 구조를 유지하고, R2 접근 키 발급도 필요 없음 |
| 재생 중 건너뛰기 | `/m/*` 미디어 경로에 구간 요청(Range) 지원 추가 |
| 무료 한도 | 동영상도 같은 용량 한도에 포함. MVP에서는 길이 제한(예: 3분) 권장 |

## 2. 중복 자동 분류 (지금 기능 확장)

지금은 완전히 같은 파일(sha256)과, 크기를 바꾸거나 다시 압축한 사진(dHash)을 찾습니다. 여기에 다음을 더합니다.

| 묶음 | 판단 기준 | 제안 |
|---|---|---|
| 연속 촬영 | 같은 카메라, 몇 초 안에 찍힘, 모양이 비슷함 (dHash) | 가장 선명한 1장 추천 (선명도 점수). "23묶음 정리하면 1.2GB 절약" |
| 카톡으로 받은 사본 | 촬영 정보 없음, 해상도 낮음, 원본과 모양이 같음, 파일 이름 `KakaoTalk_` | 원본이 있으면 사본 정리 제안 |
| 동영상 중복 | 길이가 ±0.5초 안에서 같고, 장면 8개의 모양이 일치 | 다시 압축한 영상과 메신저로 받은 영상을 찾아 고화질본을 남김 |
| 스크린샷·저장 이미지 | 파일 이름, 촬영 정보 없음, 화면 해상도와 일치 | "추억 아님" 칸으로 분리 |

**원칙: 자동으로 지우지 않습니다.** "정리 제안함"에 모으고, 사용자가 확인한 뒤에 정리합니다.
그러려면 **휴지통(30일 보관)이 먼저 필요합니다** (지금은 즉시 삭제).

## 3. 카테고리 자동 분류 (비용이 낮은 순서)

### 1단계: 규칙 기반 (0원)
- **사진 종류:** 스크린샷, 셀카(전면 카메라 정보), 파노라마(가로세로 비율), 연사, Live Photo, 동영상, 슬로모션, 타임랩스, 편집본
- **이벤트 묶음:** 촬영 시각이 6시간 이상 끊기는 지점과 위치 변화로 나눕니다. 예: "2026년 5월 · 제주 · 3일 · 412장"
- **여행 감지:** 가장 자주 찍힌 위치를 "집"으로 보고, 집에서 먼 묶음을 여행으로 표시합니다.
- **지명 붙이기:** 외부 API 없이 한국 시·군·구 경계 데이터를 앱에 넣어 브라우저에서 찾습니다. 비용이 없고 위치가 밖으로 나가지 않습니다.

### 2단계: 기기 안에서 도는 AI (0원, 사진이 밖으로 나가지 않음)
- 이미지와 문장을 함께 이해하는 소형 모델(CLIP 계열)을 브라우저에서 실행합니다 (WebGPU, ONNX Runtime Web 또는 Transformers.js).
- 썸네일(512px)마다 특징 벡터를 한 번 계산해 두면 다음이 가능합니다.
  - **카테고리:** 음식, 바다, 산, 아기, 반려동물, 문서·영수증, 생일·케이크 등 미리 정한 목록으로 분류
  - **문장 검색:** "눈 오는 날 아이", "할머니 생신". 한국어 검색은 다국어 모델이 필요해서 모델 선택이 중요합니다.
  - **비슷한 사진:** dHash보다 정확한 유사 묶음
- 저장 위치
  - 이 PC 사진: IndexedDB
  - 클라우드 사진: Postgres(Neon) pgvector. int8로 압축하면 사진 한 장에 약 0.5KB
- 비용: 모델을 처음 한 번 내려받습니다 (수십~100MB대). 처리 속도는 기기마다 크게 다르고 10만 장이면 몇 시간이 걸릴 수 있어서, 쉬는 시간에 이어서 처리하도록 만듭니다.

### 3단계: 나중에
- **얼굴 묶기:** 생체정보라 별도 동의와 법률 검토가 필요합니다 ([developer-guide.md](developer-guide.md) 14단계).
- **서버 AI** (Workers AI 등): 비용이 생기므로 유료 플랜 이후 검토합니다.

카테고리는 사진에 태그를 박아 넣지 않고 **계산해서 보여주는 스마트 앨범**으로 만듭니다.
사용자가 고친 결과만 저장하면, 모델을 바꿔도 다시 계산하면 됩니다.
