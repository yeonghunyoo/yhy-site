# nuvo 서비스 계획

2026-11-04 재조정. **예전 MVP 목표(무료 사용량 안에서 운영)는 무효**이고, 이 문서가 nuvo의 목표 기준입니다.
지금 코드가 무엇을 하는지는 [mvp.md](mvp.md)(현재 구현 기록)에, 웹·모바일별 업로드·다운로드 등 규칙은 [platform-policy.md](platform-policy.md)에, 보안·스토어 정책은 [media-security.md](media-security.md)에 있습니다. 둘이 다르면 이 문서가 목표, mvp.md가 현재 상태입니다.

## 한 줄

**휴대폰 앱에서 구독·백업·가족 공유하고, PC 웹은 큰 화면 감상과 관리.** 결제는 앱 스토어에서만 받고, 앱에서 구독하면 웹의 유료 기능도 열린다.

## 목표 (11/04 결정)

- **실제 서비스로 운영합니다.** 무료 사용량 안에 맞추는 것이 목표가 아닙니다. 비용은 구독 수입으로 감당합니다.
- **제품의 중심은 모바일 앱입니다.** 사진은 휴대폰에서 찍히니 백업·공유도 휴대폰에서 일어납니다. 휴대폰 사진첩은 웹 브라우저가 계속 읽을 수 없어서 네이티브 앱이 필요합니다.
- **웹은 확장입니다.** PC 큰 화면으로 감상, PC 폴더 보기, 구독·계정 관리. 결제 기능은 웹에 두지 않고 **앱 설치를 안내**합니다.
- **클라우드 저장은 선택 구독, 개인당 10GB.** 결제는 **앱 스토어(iOS IAP, Google Play 결제)에서만** 합니다. 앱에서 구독하면 같은 계정의 웹에서도 유료 기능이 열립니다.
- **개발 순서는 웹(서버) 먼저, 모바일을 붙입니다.** 계정 이전·용량·구독 상태·약관·신고 기능은 모두 서버 일이라 웹에서 먼저 만들고, 앱은 그걸 그대로 씁니다. 다만 설계는 처음부터 앱 결제 기준으로 잡습니다.

## 기능 구분

| 구분 | 무엇 | 서버 비용 |
|---|---|---|
| 기본 (구독 없이) | 휴대폰 사진첩·PC 폴더 보기, 기기 안 중복 찾기·정리 제안, 기기 안 분류 | 거의 없음 |
| **초대받은 가족 (구독 없이)** | 구독자가 만든 Space **보기** — 타임라인·피드·실시간 알림 | 미디어 조회(R2 B급·엣지 캐시), DB 조회 |
| 구독 | nuvo 클라우드 10GB: 백업, 다른 기기에서 보기, Space 만들기·공유 | R2 저장·요청, DB |

**11/04 결정: 가족은 구독 없이 본다.** 구독자 한 명이 Space를 만들어 가족을 초대하면, 초대받은 사람은 계정만 만들고 구독 없이 Space를 봅니다. 돈 내는 사람은 한 명, 보는 사람은 여럿. 구독 없이 Space에 **올리기**까지 되는지는 아래 "정할 것"(제안: 올릴 수 있고 용량은 Space 소유자 몫).

## 결제 구조 (11/04 결정)

| 장소 | 결제 | 비고 |
|---|---|---|
| **iOS 앱** | IAP 구독 | 심사 규정상 필수([media-security.md](media-security.md) 3.4). 수수료 15%(소규모) |
| **Android 앱** | Google Play 결제 구독 | 앱 안에서 팔면 Play 결제 필수. 한국은 2026-12-31부터 Billing Choice(최저 10%) 적용 예정([media-security.md](media-security.md) 4.5) |
| **웹** | **없음** | "앱에서 구독하세요" + 스토어 링크. 웹은 스토어 규칙 밖이라 자유롭게 안내 가능 |

- 서버는 Apple·Google **영수증 검증과 구독 상태 알림(서버 간 통지)**을 받아 한 곳에서 "이 계정은 구독자"를 판단합니다. 웹·앱 모두 이 판단 하나를 봅니다.
- 같은 계정이 두 스토어에서 중복 구독하지 않게 막습니다(이미 구독 중이면 다른 쪽 결제 화면을 숨김).
- 해지·환불은 결제한 스토어에서만 됩니다. 앱의 "구독 관리"는 해당 스토어 화면을 엽니다. 웹에는 "결제한 스토어에서 관리"를 안내합니다.
- **두 스토어 가격은 같습니다**(11/04 결정). 규정상 의무는 없지만 결제 수단이 스토어 둘뿐이고, 가족 안에서 iPhone·Android가 섞여 있을 때 가격이 다르면 설명이 안 됩니다.
- 웹 PG 정기결제는 넣지 않습니다. 그래서 PG 계약·빌링키 관리가 없고, 통신판매업 신고 등 사업 요건은 스토어 판매 기준으로 확인합니다.

## 용량과 원가

- 개인 10GB는 R2 저장 원가로 한 달 약 0.15달러입니다(무료 10GB를 넘는 분 GB당 월 0.015달러, 전송료 없음). 요청 수 비용은 별도로 작습니다.
- 계정의 R2 무료 10GB는 구독자 한 명이면 찹니다. **유료 서비스로 가려면 nuvo를 자기 Cloudflare 계정으로 옮기는 것이 먼저**입니다(루트 [`docs/monorepo.md`](../../../docs/monorepo.md) "Cloudflare·Resend 계정"). 지금은 portfolio-web과 계정을 같이 써서 8GB 상한을 코드로 걸어 두었습니다(mvp.md "계정 공용 한도").
- Workers는 실서비스라면 유료 플랜(월 5달러)을 기준으로 잡습니다. 무료 플랜은 하루 요청 수와 요청당 CPU 시간 제한이 있습니다.
- Neon(Postgres)은 사용자가 늘면 무료 한도를 넘습니다. 플랜과 비용은 출시 전에 확인합니다.
- 가격은 스토어 수수료(iOS 15%, Android 15% → 한국 Billing Choice 후 10%대)를 뺀 금액이 원가와 고정비를 넘도록 정합니다.
- 예전 유료 플랜 후보(Space 단위 100GB, 월 3,900원)는 무효입니다. 용량은 **사람 단위**로 묶습니다.

## 모바일

| 방식 | 장점 | 단점 |
|---|---|---|
| **Capacitor** (지금 React SPA를 앱으로 감싸고, 사진첩·결제만 네이티브 플러그인) | 화면·타임라인·중복 정리·API 코드를 그대로 씀 | 수만 장 그리드 스크롤 성능을 확인해야 함. 썸네일은 웹 디코딩 대신 네이티브 API로 받아야 함. 심사 4.2 "웹사이트 재포장" 거절 위험 — 사진첩 접근·백그라운드 업로드가 차별 근거 |
| **Expo / React Native** | 사진첩 라이브러리가 성숙하고 스크롤이 빠름 | 화면을 다시 만들어야 함. 공유 가능한 건 API 타입·로직(`@nuvo/shared`) 정도 |

- 제안: 화면을 그대로 쓰는 Capacitor로 시작하고, 실기기에서 스크롤·썸네일 성능이 부족하면 그 화면만 네이티브로 바꿉니다. 정할 것에 남깁니다.
- 지금 기기 간 "같은 사진" 판정은 파일 전체 sha256입니다. 휴대폰에서는 다음이 걸립니다. 앱 설계 때 판정 기준을 따로 정합니다.
  - 사진첩 전체를 해시하면 배터리와 시간이 많이 듭니다.
  - iCloud "저장 공간 최적화"를 켜면 원본이 기기에 없습니다.
  - PC로 옮기면서 HEIC가 JPEG로 바뀌면 같은 사진이어도 해시가 다릅니다.
- 자동 백업은 "즉시"가 아니라 **앱을 열 때·충전 중 유휴 때** 이어서 올립니다. 앱이 꺼진 상태에서 새 사진을 바로 올리는 건 iOS에서 불가([media-security.md](media-security.md) 3.5).
- 스토어 심사가 요구하는 기능([media-security.md](media-security.md) 6절): 사진 신고·멤버 차단·공개 연락처·약관 동의, iOS Sign in with Apple, Android 웹 계정 삭제 페이지. 앱 전에 웹에 먼저 넣어 둡니다.
- 동영상 공유용 사본은 휴대폰 OS 인코더로 만드는 것이 기본입니다([roadmap-video-classification.md](roadmap-video-classification.md) V9). 웹 WebCodecs는 PC 폴더 동영상용.

## 웹 (PC)

- 역할: 큰 화면 타임라인·Space 감상, PC 폴더 보기(Chrome·Edge, 지금 구현), 중복 정리, 계정·구독 관리(해지는 스토어 안내), 계정 삭제 페이지(Android 요건).
- 결제 화면 대신 **앱 설치 안내**(스토어 링크·QR). 웹에서 "앱이 더 싸다/비싸다"는 말은 할 필요가 없습니다(가격 동일).
- Safari·Firefox는 폴더를 열 때마다 다시 골라야 합니다(mvp.md "알려진 한계"). 데스크톱 앱(Tauri)은 웹으로 부족한 점이 확인되면 그때 정합니다.

## 출시 전 할 일 (사람)

- 스토어 개발자 계정(Apple Developer, Google Play Console), 사업자등록, 세금 정보. 통신판매업 신고 필요 여부는 스토어 판매 기준으로 확인.
- 이용약관의 결제·해지·환불(청약철회) 조항은 스토어 환불 정책과 맞춤. 개인정보처리방침([developer-guide.md](developer-guide.md) 14단계)에 결제·스토어 식별자 추가.
- 구독이 끝났을 때 저장된 사진을 어떻게 할지(읽기 전용 기간, 내려받기 기간, 삭제 시점)를 약관에 적습니다.

## 순서

| 단계 | 내용 |
|---|---|
| **1차 웹(서버)** | ① nuvo를 자기 Cloudflare·Resend 계정으로 옮기기 ② 용량 모델: 개인 10GB, 구독 상태로 업로드 허용(서비스 전체 8GB 상한은 비용 알림으로 대체) ③ 구독 상태 모델 — Apple·Google 영수증을 받을 자리로 설계, 1차에는 운영자가 수동으로 켜는 구독 플래그 ④ 약관·개인정보처리방침 ⑤ 신고·차단·공개 연락처·약관 동의 ⑥ Sign in with Apple(웹에도) ⑦ 계정 삭제 웹 페이지 ⑧ 웹에 "앱에서 구독" 안내 자리 |
| **2차 모바일** | ① Capacitor 감싸기 + 사진첩 보기 + 초대받은 Space 보기(구독 없이) ② iOS IAP·Google Play 결제 + 서버 영수증 검증·통지 ③ 백업(골라서 → 자동) ④ 스토어 심사 문서(Privacy Manifest, Data safety, 권한 선언 폼, 연령 등급) |
| **3차** | 동영상·자동 분류([roadmap-video-classification.md](roadmap-video-classification.md)), 무료 범위 조정 |

1차가 끝나면 **구독자가 없는 상태의 완성된 서비스**입니다(운영자가 수동으로 켠 계정만 업로드 가능). 2차가 끝나야 돈을 받습니다.
