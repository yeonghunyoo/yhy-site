### 1. 운영 벡터 맞추기 + 동기화 토큰 — 지금 (약 10분, 사람: 토큰 보관)

왜 먼저: 운영 D1은 163청크인데 Vectorize는 133개다. 새 30개(클러쉬(주)·nuvo·프로젝트 페이지)는 키워드로만 찾히고 벡터 검색에는 안 걸린다. 11/04 배포(3c9af886)는 토큰이 없어 동기화를 건너뛰었다.

1. 토큰 만들기: `openssl rand -base64 32`
2. 운영 비밀 등록: `./node_modules/.bin/wrangler secret put RAG_SYNC_TOKEN` (값 붙여넣기). 비밀은 등록 즉시 Worker에 반영된다 — 재배포 필요 없음
3. 로컬 `.prod.vars`에 `RAG_SYNC_TOKEN=…` 한 줄 추가(커밋 안 됨, `--secrets-file`은 추가 방식이라 이 줄만 있어도 다른 운영 비밀은 그대로). 이후 `pnpm run deploy`가 배포 뒤 자동으로 동기화한다
4. 첫 동기화: `pnpm rag:sync:remote` → `RAG 청크: 로컬 N / 운영 D1 163` 줄과 벡터 갱신 결과(새 30·지울 3 근처)가 나오면 성공. 토큰이 틀리면 404
5. 확인: `/admin/chat`에서 자식 수 = 벡터 수(163). KV `rag:vector-ids`도 이때 채워진다
- 토큰 등록이 싫으면 대신 `/admin/chat` → **벡터 갱신** 한 번(관리자 세션). 이 경우 다음 문서 수정 때도 손으로 눌러야 한다

### 2. 문서 내용 채우기 — 사람이 정해야 함

챗은 문서에 있는 것만 말하므로 이 단계가 답의 질을 정한다. 셋 다 고친 뒤 `pnpm rag:build`(로컬) → 로컬 `/admin/chat?eval=1`로 재현율이 떨어지지 않았는지 보고 → 커밋 → `pnpm rag:sync:remote`(또는 배포).

한국어 문서를 고쳤으면 커밋 전에 `pnpm rag:translate`로 영어 번역본을 갱신한다(손으로 쓴 영어 문서는 건드리지 않는다).

2-1. **FAQ** — 완료(11/04). 8개: 연락, 지금 일하는 곳, 주로 하는 일, 원격 근무·근무 지역(원격 지향, 출근은 서울·경기), 이력서(지금은 레터로 요청), 코드 위치(GitHub 링크), 사이트 기술, 챗 동작. 답에는 주어 "유영훈"을 쓴다(영어 번역이 1인칭 "I"로 나오지 않게). 근무 형태(정규직·계약 등)는 넣지 않았다
- 이력서 자동 발송 **[결정 대기]**: 레터로 이력서를 요청하면 작성해 둔 문서를 자동으로 보내는 기능(사용자 예정 작업). 레터(3단계) 확장 — 메일 상한·봇 방지와 함께 설계하고, 만들면 FAQ "이력서" 답을 바꾼다

2-2. **스택 경험 수준** — 완료(11/04). 실무 / 개인 프로젝트 두 단계, 문서에 근거가 있는 것만(`stack.{ko,en}.md`). 클러쉬(주)에서 쓰는 개별 기술 이름은 넣지 않았다

2-3. **추천 칩·인사말·페르소나** (`src/i18n/{ko,en}.json`의 `chat.greeting`·`chat.chips`, `src/lib/server/chat.ts`의 `systemPrompt`)
- 지금: 인사 "저는 yhy의 포트폴리오 에이전트예요…", 칩 3개(프로젝트 / 기술 / 연락) — 칩 3개 방향은 확정(05-06 "추천 질문 칩")
- 다듬을 것: 칩을 실제 문서로 확실히 답이 나오는 질문으로(예: "Forest는 어떤 앱이에요?", "RAG는 어떻게 만들었어요?"). 칩마다 로컬에서 한 번씩 눌러 답·출처 칩 확인
- 인사말은 1문장 + 칩. 페르소나 규칙(1인칭 금지, 합니다체)은 11/03 그대로 두고, 바꾸면 `?redteam=1`을 다시 돌린다

## 2. Cloudflare 설정

### 2-1. Vectorize 인덱스 + 바인딩 — 완료 (11/01)

인덱스는 `wrangler vectorize create portfolio-rag --dimensions=1024 --metric=cosine`으로 만들었고, `wrangler.jsonc`에 `ai`·`vectorize` 바인딩(둘 다 `remote: true`)을 넣었다. 바인딩을 바꾸면 `pnpm cf-typegen`.

- API 키가 필요 없다. 답변·재작성·임베딩·리랭크 모두 `AI` 바인딩 하나로 부른다
- `astro build`는 원격 연결을 열지 않는다(`astro.config.mjs`의 `remoteBindings`, 11/02) — 빌드 중 정적 페이지 생성은 AI·Vectorize를 쓰지 않으므로 Cloudflare 로그인 없이도 빌드된다. 배포된 Worker의 바인딩은 그대로다
- 로컬 `wrangler dev`(`pnpm preview`)도 AI·Vectorize는 원격을 쓴다 — 로컬 질문도 Workers AI 무료 범위에 잡히고, 로컬에서 벡터 갱신을 누르면 운영과 같은 인덱스가 바뀐다
- 무료 한도: Workers AI 하루 1만 뉴런, Vectorize 월 3천만 쿼리 차원 — 이 규모에선 여유. 계정이 무료 플랜이면 한도를 넘는 Workers AI 호출은 실패하고, 챗은 "오늘은 쉬어요"로 끝난다

### 2-2. 운영에 켜기

```bash
pnpm db:migrate:remote          # 챗·RAG 마이그레이션(0002~0005)
pnpm rag:build:remote           # 문서 → 운영 D1
./node_modules/.bin/wrangler secret put CHAT_ENABLED            # 값: 1
./node_modules/.bin/wrangler secret put CHAT_MONTHLY_TOKEN_CAP  # 선택, 예: 2000000
PUBLIC_CHAT_ENABLED=1 pnpm run deploy                          # 챗 독은 빌드 플래그가 있어야 화면에 나온다
```

배포 뒤 `/admin/chat` → **벡터 갱신**, 자식 수와 벡터 수가 같은지 확인.

두 개의 스위치가 있다: `PUBLIC_CHAT_ENABLED`(빌드 — 독 버튼 노출), `CHAT_ENABLED`(런타임 — API 열기). 끌 때는 `CHAT_ENABLED`를 지우면 API가 즉시 404가 된다.
